# Codex 开发任务：为 LENS · 知微实现纯代码驱动的电影级开场动画

项目地址：https://github.com/Fwlyii/data-analysis-frontrefine

## 一、核心要求：必须使用实时渲染动画，禁止视频播放方案

请为现有 LENS 可视化交互系统开发一段约 5—6 秒的电影级全屏入场动画。

**最重要的要求：整段动画必须由前端代码实时生成和驱动。**

明确禁止：

- 使用 MP4、WebM 等预渲染视频作为开场画面。
- 使用 GIF 代替动画。
- 使用连续图片或精灵图模拟视频播放。
- 使用预渲染逐帧动画或 Lottie 成品动画代替主要实现。
- 将生图模型生成的整幅页面图片用作动画主体。
- 仅使用简单的淡入淡出、Loading 图标或者文字打字效果敷衍实现。

推荐技术组合：

1. **Canvas 2D**：实现实时粒子系统、粒子轨迹、数据流、深度层次和光点汇聚。
2. **SVG**：实现透镜、精密光学环、扫描线、动态路径和科学图形。
3. **CSS 3D Transform / Filter / Mask**：实现空间透视、发光、景深和遮罩效果。
4. **Motion mini / Web Animations API**：实现高级时间轴、文字揭示和页面转场。
5. **requestAnimationFrame**：驱动需要逐帧计算的动态场景。

优先复用项目已经引入的 Motion mini，不要无故增加大型第三方动画依赖。

我要的不是网页播放一段视频，而是**网页本身像电影一样运动起来**。

## 三、动画分镜与实时实现

### 第一阶段：黑暗中的数据觉醒（0—0.8 秒）

画面从黑暗中渐渐亮起。

Canvas 中随机分布少量具有不同景深的微光粒子。

实现细节：

- 粒子具有不同大小、透明度和运动速度。
- 使用确定性随机种子，保证每次播放整体构图稳定。
- 用径向渐变绘制柔和的局部辉光。
- 通过速度和缩放差异模拟前后景。
- 背景逐渐显现极淡的科学坐标网格。

视觉要有明显的空间深度，避免普通二维星空屏保的感觉。

### 第二阶段：数据流汇聚（0.8—1.8 秒）

粒子由无序漂移转为有组织的数据流。

实现细节：

- 使用曲线轨迹、速度场或吸引力模型驱动粒子。
- 数据粒子从画面两侧向中央流动。
- 流动形成具有节奏变化的空间曲线。
- 少量线段连接邻近粒子，逐渐呈现数据网络。
- 粒子向中心加速，建立视觉张力。

使用真正的粒子运动计算，不要把静态背景图片直接平移。

### 第三阶段：光学透镜形成（1.8—3.0 秒）

粒子汇聚形成品牌核心——智能透镜。

使用 SVG 和程序化动画实现：

- 多层同心圆环。
- 不同角度的光学弧线。
- 半透明镜面。
- 细致的扫描线。
- 中心聚焦光点。
- 轻微旋转与空间倾斜。

圆环应当逐步形成并锁定，随后光束穿过透镜。

形成过程必须和上一阶段的粒子汇聚连续衔接。

不要突然凭空显示一个圆圈。

### 第四阶段：数据洞察（3.0—4.0 秒）

透镜扫描后，短暂出现五种科学图形意象，对应系统原有五项研究：

1. 简洁作答
2. 中文数学
3. 限长反弹
4. 资料位置
5. 反馈修复

可以使用 SVG 路径动画、动态柱状结构、节点移动和代码符号等形式。

这些图形是抽象视觉语言，不需要伪造任何实验数值。

**不能改变真实数据，也不能对原有科学曲线添加虚假的中间数据点。**

五种图形短暂形成后，逐渐收束为中央的品牌光点。

### 第五阶段：品牌揭幕（4.0—5.0 秒）

光点向外扩散，显现：

**LENS.**

然后出现：

**知微**

最后浮现系统副标题。

实现要求：

- 文字必须是原生 HTML/SVG 文本，保证清晰度与可访问性。
- 优先复用已有品牌字体和艺术字设计。
- 使用遮罩揭示、错峰入场、轻微字距变化等高级排版动画。
- 不使用普通打字机效果。
- 不堆砌复杂文字特效。
- 品牌需要具有足够的视觉停留时间。

## 四、关键设计：代码驱动的无缝镜头穿越

这是本次任务最重要的部分。

动画结束后，必须让用户感觉镜头真正进入了 LENS 系统。

建议使用如下方案：

1. 中央透镜重新发光。
2. 使用 SVG / CSS 的 scale、clip-path、transform 等属性让透镜向观察者快速靠近。
3. 透镜逐渐扩大至覆盖全屏。
4. 通过遮罩过渡，使深蓝背景逐渐显露现有的浅蓝白色页面。
5. 利用共享元素转场思想，将开场中的 LENS 品牌标识缩小并移动至现有网页左上角品牌位置。
6. 原有顶部导航、标题、科研主图依次出现。

请考虑使用 FLIP（First–Last–Invert–Play）或同等的共享元素动画方法，通过测量真实 DOM 元素的位置，实现品牌从封面中央到网页页眉的空间连续性。

**不能以简单地隐藏封面、显示首页来替代完整转场。**

转场结束后必须显示原有的真实可操作界面，不能使用模拟首页图片。

## 五、可选增强：让动画更有生命力

在保证性能、连贯性和美观的前提下，可以适当加入：

- 粒子流的拖尾。
- 透镜微弱的呼吸式光晕。
- 透镜扫描时的光线折射感。
- 近景和远景之间的视差。
- 根据透镜运动方向变化的微弱拖影。
- 通过时间轴同步控制粒子、透镜、文字与背景。
- 细腻的速度缓入缓出。

这些效果应该服务于镜头语言，而不是为了炫技而叠加。

不要使用持续闪烁、过强模糊和大量高亮粒子。

## 六、技术架构要求

请将动画设计成独立的前端模块。

建议划分为：

- IntroController：控制播放状态、时间轴、跳过和重播。
- ParticleSystem：计算并绘制粒子。
- LensScene：绘制和控制光学透镜。
- TitleReveal：控制品牌文字入场。
- PageTransition：实现从封面到真实主页的共享元素转场。

可以根据现有工程结构调整模块划分，不必机械创建大量文件。

要求：

- 使用统一时间轴同步各个场景。
- 保证跳过、重新播放和页面隐藏时可以正确取消动画。
- 避免重复注册监听器。
- 正确清理 requestAnimationFrame。
- 正确处理窗口尺寸变化。
- 使用 devicePixelRatio 适配高清屏。
- 限制过高的 Canvas 渲染分辨率，避免高 DPI 设备消耗过大。
- 不允许动画阻塞主系统的数据初始化。

开场只播放有限时长，不保留不必要的无限运行粒子循环。

## 七、性能和移动端

目标：

- 桌面设备尽可能稳定达到 60 FPS。
- 移动端优先保证流畅，可采用 30 FPS 或降低粒子复杂度。
- 不引入大型 3D 引擎，除非有充分理由。
- 尽量控制新增 JavaScript、CSS 和静态素材的体积。
- 避免大量昂贵的实时模糊滤镜和逐帧 DOM 布局测量。
- Canvas 绘制和 DOM 动画职责分离。

建议根据设备性能与屏幕尺寸动态调整：

- 粒子数量。
- 发光效果强度。
- 连接线数量。
- 渲染分辨率。
- 背景装饰层数。

即使在普通笔记本与手机上，也应保持完整的主要视觉节奏。

## 八、用户交互

必须支持：

1. 首次进入首页时自动播放。
2. 右上角提供“跳过片头”。
3. 首页提供低调的“重播开场”入口。
4. 同一浏览会话内，从图表库返回首页时不重复播放。
5. 通过 `?intro=1` 强制播放，方便课堂演示。
6. 通过 `?intro=0` 跳过，方便调试。
7. 尊重 `prefers-reduced-motion`，必要时直接显示主界面。
8. 动画出错时自动回退到正常系统。
9. 保持已有章节深链接、图表库导航和浏览器历史行为。

不得因为动画而导致原页面无法滚动、无法点击或键盘焦点丢失。
