# 任务：基于生图模型与 Coding Agent 的现有前端全自动视觉优化

## 一、任务目标

当前项目已经有可以正常运行的前端页面。现在需要在保留现有网站主要布局、内容和功能的前提下，通过生图模型与 Coding Agent 协同，提高页面的审美质量、视觉层次、设计感和整体完成度。

本次不是从零开发网站，也不是简单修改 CSS，而是尝试实现一个完整的：

**现有网页 → 浏览器截图 → 生图模型优化视觉设计 → 独立素材生成 → 前端代码修改 → 浏览器视觉反馈 → 自动迭代优化**

的闭环。

请自主完成研究、规划、执行和验收。除非遇到权限、费用、凭证或关键能力缺失等必须由我决定的问题，否则不需要中途征求我的同意。

本次先选择当前项目的主要前端页面进行 Pilot。如果我已经明确指定目标路由，以指定路由为准；否则优先选择默认首页。

## 二、必须参考的研究论文

请首先阅读以下论文，理解其核心方法，并判断如何应用到当前项目。

### 论文一：Editable Visual Design（核心参考）

https://arxiv.org/abs/2609.04034

开源项目：

https://github.com/yejy53/Editable-Design

重点研究：

- VLM 如何负责设计规划与视觉评价。
- 生图模型如何作为视觉想象器参与设计。
- 如何先生成视觉参考，再通过代码实现。
- 如何将复杂艺术素材与 HTML/CSS 分离。
- 如何保持文本、布局和视觉素材的可编辑性。
- 如何通过渲染截图进行视觉反馈和自动修复。

特别注意：这篇论文主要面向海报、信息图等视觉作品。不要直接照搬其固定画布实现，而应将其方法适配到现有响应式网页。

### 论文二：UI Remix

https://arxiv.org/abs/2601.18759

重点研究：

- 如何对已有 UI 进行局部设计改造。
- 如何避免优化过程中偏离原始设计。
- 如何保留原有内容及主要结构。
- 如何将新的设计风格应用到已有组件。

### 论文三：UI2Code-N

https://proceedings.mlr.press/v306/yang26v.html

重点研究：

- 如何通过浏览器截图评价真实页面。
- 如何比较视觉设计目标与代码实现结果。
- 如何进行迭代式 UI Polishing。
- 如何根据视觉反馈生成局部代码修改。

阅读后，先在内部制定具体技术方案，再开始执行。

## 三、总体约束

必须遵守以下要求：

1. 不改变现有网站的主要业务逻辑。
2. 不删除已有功能。
3. 不随意修改接口、路由和状态管理。
4. 不大幅改变页面的信息架构。
5. 不将完整页面替换成一张图片。
6. 不为了视觉效果破坏响应式布局。
7. 不为了动效引入明显的性能问题。
8. 普通文本、按钮、表单和图表必须保持为真实前端组件。
9. 优先复用当前项目的技术栈和组件体系。
10. 所有修改必须能够回退。

优化重点为：

- 色彩搭配
- 字体与排版
- 页面层次
- 留白和间距
- 卡片及容器设计
- 光影和质感
- 图标和艺术装饰
- 页面整体一致性
- 适度的交互动效

目标是让原有页面变得更精致，而不是重新设计成另一个网站。

## 四、第一阶段：项目分析与原始截图

请先检查项目当前状态。

1. 阅读前端代码及项目结构。
2. 确认采用的框架、组件库及样式方案。
3. 检查是否存在未提交的代码修改，保留用户现有改动。
4. 建立安全的工作分支或其他可恢复的修改记录。
5. 找到目标页面对应的路由和组件。
6. 安装或使用项目已有依赖，启动前端开发服务器。
7. 使用 Playwright 等浏览器自动化工具打开页面。
8. 获取桌面端及移动端截图。

建议至少检查：

- 桌面端：1440×900
- 移动端：390×844

如果页面需要登录，请使用项目已有的合法测试方式或测试数据，不得绕过权限控制。

保存原始截图，并记录：

- 页面主要区域
- DOM 和组件结构
- 字体、颜色和间距
- 现有图片与图标
- 关键交互
- 需要保持不变的内容

将这些作为后续设计的约束依据。

## 五、第二阶段：生图模型进行视觉优化

这是本次任务最重要的阶段。

必须调用真正具备图片生成或参考图编辑能力的模型。

不能仅让 VLM 阅读截图后输出 CSS 修改建议，就认为已经完成生图设计。

### 1. 生成视觉优化方案

将原始网页截图作为参考图，使用图像编辑或参考图生成能力，产生两个不同的视觉优化方案。

生成时必须明确要求：

- 保留原始页面的信息架构。
- 保留主要组件的位置及相互关系。
- 保留导航、表单、图表和内容区域。
- 保留原始文字内容，不虚构新的业务信息。
- 保留网站原有的主要视觉身份。
- 优化色彩、排版、层次、质感和装饰。
- 不做大规模重新排版。
- 不改变功能组件的语义。

可以对局部区域采用遮罩编辑。

生图模型可以充分发挥其设计能力，但必须在原有页面的结构约束下进行。

### 2. 自动比较两个方案

请使用 VLM 对两个方案进行视觉评价。

评价维度：

- 美观程度
- 视觉层次
- 风格一致性
- 信息可读性
- 原始布局保留程度
- 代码实现可行性
- 是否适合响应式网页

不要只选择视觉最惊艳的方案。

应优先选择具有明显审美提升、同时能够较好保留原网页结构的方案。

保存两个设计方案及选择理由，并自动选定综合表现更好的版本继续执行。

## 六、第三阶段：视觉设计解析与素材生成

读取选中的设计图，将视觉元素分为三类。

### A 类：由代码实现

包括：

- 字体与排版
- 普通按钮
- 卡片
- 边框
- 阴影
- 圆角
- 渐变
- 布局
- 普通几何装饰

使用 CSS、HTML、SVG 或现有组件库实现。

### B 类：独立视觉素材

包括：

- 特殊艺术插画
- 复杂背景
- 科技纹理
- 非标准装饰图形
- 难以直接通过代码实现的视觉元素

优先要求生图模型根据选定的设计稿单独生成这些素材。

尽可能使用透明背景 PNG、WebP 或 SVG。

如果生成模型无法直接输出透明背景，可以在必要时采用抠图或背景移除方法。

特别注意：

**优先独立生成素材，不要简单从完整设计图中裁剪。**

只有在素材边缘清晰、背景不受污染、分辨率足够时，才考虑直接裁剪。

### C 类：必须保持原生的元素

包括：

- 正文和导航文字
- 普通标题
- 表单
- 按钮文字
- 数据图表
- 动态数据
- 可交互组件

这些必须保留为真实代码。

不要将文字直接截成图片。

如果生图模型设计出特殊字体，应优先寻找许可合适的字体文件，再通过 CSS 实现。

只有非交互性的特殊艺术字或品牌装饰，才可以考虑独立图片形式。

## 七、第四阶段：修改现有前端代码

根据已经确定的设计方案，对现有页面进行局部修改。

具体要求：

1. 优先修改样式和必要的组件结构。
2. 保留当前组件的数据和交互逻辑。
3. 保留接口及路由。
4. 将独立素材正确接入项目。
5. 尽量复用现有设计变量及公共组件。
6. 避免引入大量重复 CSS。
7. 不要通过绝对定位硬凑整个页面。
8. 确保桌面和移动端均可正常显示。

对于特殊动效，可以使用现有项目支持的动画方案，必要时考虑 View Transitions API 或兼容 Vue 的动画库。

但动效不是本次优化的主要目标。

## 八、第五阶段：视觉反馈与自动迭代

完成第一版代码修改后：

1. 重新启动或刷新页面。
2. 在与原始截图相同的浏览器尺寸下截图。
3. 将真实网页截图与选定的生图设计方案进行比较。
4. 使用 VLM 分析视觉差异。
5. 找出影响最大的设计问题。
6. 修改相关组件或样式。
7. 重新渲染和截图。

最多进行三轮主要视觉优化。

每一轮需要检查：

- 页面结构是否保持正确。
- 是否存在元素缺失。
- 是否发生文本溢出。
- 是否出现图片遮挡。
- 是否出现布局错位。
- 设计风格是否统一。
- 是否与选定方案更加接近。
- 是否出现性能和交互退化。

优先修复局部问题，不要每一轮都重新生成整个页面。

如果某一轮修改导致明显退化，请回退该轮相关修改。

## 九、第六阶段：功能和性能验收

请使用浏览器自动化进行功能回归测试。

至少验证：

- 页面能够正常访问。
- 导航和路由正常。
- 按钮能够正常交互。
- 表单和弹窗没有被破坏。
- 图表或动态数据仍然正常显示。
- 不存在明显的横向溢出。
- 不存在严重的布局遮挡。
- 移动端显示正常。
- 浏览器控制台没有新增严重错误。

再通过 Lighthouse 或同类性能工具进行检查。

特别关注图片体积、加载速度和交互流畅度。

不要为了视觉效果让网页性能明显下降。

### 2. 视觉方案

提供：

- 原始网页截图

### 3. 修改内容

列出：

- 修改的组件和文件

- 新增的独立素材

### 4. 验收结果

提供：

- 视觉对比
- 功能测试结果
- 响应式测试结果
- 性能检查结果

### 5. 最终结论

请客观判断：

- 生图模型是否提供了明显的设计增益？
- 最终代码实现能否还原其视觉效果？
- 是否较好保留了原始布局和功能？
- 哪些视觉元素适合生图，哪些应该继续用代码？
- 这套流程是否值得推广到整个网站？

请将截图、生成素材和报告整理到项目内单独的优化成果目录，不覆盖原始参考材料。

最终目标：

**在不大幅改变现有页面的前提下，真正利用生图模型的设计能力改善网页审美，并通过 Coding Agent 自动还原到现有前端代码，形成可复现、可评价的完整优化闭环。**

请现在开始执行，不要只输出实施计划。
