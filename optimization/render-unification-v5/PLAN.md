# 渲染修复与统一视觉流程 v5

基线：当前已发布 main 297d65e；业务参照 dataAnalysis-vision Master 35f7318。

1. 分开检查请求、图片解码、SVG/Canvas 实际绘制、可见尺寸、遮挡和滚动可达性。对正常动画、减少动画、快速导航、短屏和手机分别观察，保留失败证据。查明缺陷后再改变设计。
2. 先获取当前真实截图并记录各块的内容、占用尺寸、组件关系和数据边界；两份生图方案同时设计页面与开场终帧，覆盖桌面 1440×900、短屏 1366×768、手机 390×844。模型可选择颜色与材质，内容、控件和数据保持真实。
3. 选择统一方案，建立可供页面、SVG 展示层、Canvas 开场共同读取的颜色来源；保留模型/策略等科学颜色的区分。按需要独立生成装饰资源，不将整页参考当网页。
4. 重整样式规则并修复实际渲染问题，调整入场对象、时序与衔接，让开场的背景、光学元素和品牌落点适配新页面。减少动画、失败回退与键盘操作继续有效。
5. 用第一版真实桌面/手机截图进行至少一次定向生图反馈，记录接受与拒绝的内容，再做局部修改。
6. 对整站状态清单执行实际图像/图表渲染检查，明确等待异步绘图完成；截取可见图表和滚动后的证据/表格。再验收原交互、内容保真、无障碍、实时动画与性能。
7. 只有当前源码与最终截图/检查对应后才通过发布门禁。按本会话已有授权推送 main，等待 Pages 成功，再用公网浏览器核对实际效果和资源版本。失败先修复，不用检查数量代替视觉判断。
