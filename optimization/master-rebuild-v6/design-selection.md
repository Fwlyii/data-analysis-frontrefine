# 方案选择与视觉复核

两套候选实际生成在 [A/B 对照板](design/candidates-a-b.png) 中。以下是当前 Coding Agent 查看设计图后的定性判断，不是用户研究或客观审美评分。

| 维度 | A：编辑式观测站 | B：现代研究笔记 |
| --- | --- | --- |
| 美观 | 衬线标题与原有光学图形成较自然的研究出版物气质 | 粗体更强，标题成为更重的视觉中心 |
| 层级 | 标题、说明、三个研究方向和总量层级接近原版 | 标题的重量更突出，正文相对退后 |
| 一致性 | 容易延续到纸色内容页；图表库可统一深蓝顶栏 | 可统一界面，但会改变叙事标题的原有语气 |
| 可读性 | 采用原生字体、限制字距并实测手机断行 | Sans 标题易读，但需要重新平衡图文比例 |
| 结构保留 | 与 Master 最接近 | 位置关系大体保留，视觉重心变化更多 |
| 实现可行性 | 本地许可字体、CSS 和现有 SVG 即可完成 | 也可实现，但需要更广泛调整标题体系 |
| 响应式 | 保留原来的桌面左导航和手机底部导航 | 手机也可实现，没有足以抵消设计漂移的优势 |

选择 A。两套生成稿中的“给图表库添加整条演示侧栏”均不采用，因为会挤占真实图表宽度。图片中的图形或数值不用于替换真实图表。

第一版实现后又实际调用生图模型，以四张浏览器截图作为输入。输入原始字节归档在 `design/feedback-inputs/`；输出为 [第二轮反馈稿](design/screenshot-feedback.png)，完整提示与哈希见 `run-manifest.json`。采用其关于轨道端点、安全区、手机装饰位置和筛选器整齐排列的建议；不照搬其图表尺寸或重画的数值。

最终检查了 [桌面总览](after/review-sheet-desktop.jpg) 和 [手机总览](after/review-sheet-mobile.jpg)，并保留每个状态的原尺寸截图及 [92 状态成对画廊](review-gallery.html)。全景/发现的宽图在手机内滚动；内容长时使用原生纵向滚动，不为追求一屏塞满而压小所有字。

此次模型提供的主要价值是提前比较风格、统一多页面方向并发现局部构图问题。最后仍由真实字体、CSS、原生图表及浏览器检查决定实现。审美是否符合个人偏好需要看最终页面判断；技术检查通过不能代替这一判断。
