# 前端视觉优化流程 v2

适用：当前已运行的 LENS 原生静态前端。保留数据含义、路由、图表操作与图表库入口，按局部问题逐轮优化。2026-10-31 的第二轮样例与证据见 `optimization/type-motion-v2/`。

方法依据沿用首轮已阅读的 [Editable Visual Design](https://arxiv.org/abs/2609.04034)、[UI Remix](https://arxiv.org/abs/2601.18759)、[UI2Code-N](https://proceedings.mlr.press/v306/yang26v.html)：分别借鉴生图参考与独立素材、保留结构的局部重设计、真实渲染反馈。响应式、字体、动效及发布关卡是本项目的工程补充，不能称为论文已经验证的统一方法。原始阅读与适配记录保留于 `optimization/homepage-pilot/research/`。

## 本次反思

上一轮重点检查了配色、布局、素材与功能，但字体仍依赖操作系统回退；截图机装了字体，不等于访问者也能显示同一种字体。原来的章节过渡很短，静态截图又默认减少动态效果，缺少可感知动画设计和真实动态验收。两个问题都应成为流程关卡，不能只在最后主观评价“好看了”。

## 1. 建立可比较的基线

- 在独立分支记录基线提交、工作区状态、可发布范围。
- 打开真实页面，记录桌面、手机、全部章节和关键选择状态。保存实际字体、资源请求、页面宽度、控制可用性和当前性能。
- 明确本轮范围与受保护的数据、原始 SVG、业务逻辑。已有授权允许发布时，验收后继续完成部署；没有授权时保留可审阅本地结果。

## 2. 分开设计文字与装饰

- 建立字体层级：品牌、中文标题、正文、控件、数据标签分别承担什么作用；检查字号、字重、字距、行高与行长。
- 对关键标题选择明确许可的本地网页字体，按所有动态标题生成覆盖集合并子集化；保留版权、许可、源文件 SHA-256 与准备脚本。实际浏览器检查所用字体、缺字和换行，不能只核对 font-family。
- 生图适用于小型品牌艺术字和非信息性装饰。至少比较两个候选，检查真实缩小尺寸、背景、透明边缘与阅读性，记录没有实现的提示词意图。
- 数据标题、表单、正文、数值继续保留原生文本。生成的品牌图保留原生可访问名称和加载失败回退。
- 新增标题或替换文案时重新生成字体子集；不要沿用旧覆盖集合。

## 3. 先写动画方案，再检索 GitHub

为每项效果说明触发、对象、终态、时长、减少动态效果、快速重复触发如何处理。避免只列“加动画”。核对候选官方仓库、当前许可、API、运行体积、框架要求与本项目结构，锁版本并保留版权。本地托管必要代码。

本轮方案：

| 触发 | 可感知反馈 | 时长 | 减少动态效果 |
|---|---|---|---|
| 首次进入/章节变化 | 标题、摘要、结论、图纸轻微上移；摘要与结论淡入 | 450–550ms，延迟 0–80ms | 直接呈现终态 |
| 切换主题 | 导航下划线滑向所选章节 | 420ms | 直接定位 |
| 更换筛选条件 | 图表容器淡入与轻移 | 280ms | 即时显示 |
| 原有修复版本播放 | 更新后的图表容器短淡入 | 220ms | 原有数据播放保留，装饰淡入关闭 |
| 证据区首次进入视口 | 小幅上移、轻淡入，一次完成 | 500ms | 直接呈现 |
| 按钮悬停/按压 | 颜色、阴影、小幅位移反馈 | 150–180ms | 无位移动画 |

动画只改变展示层 transform/opacity，不插值实验数值或曲线几何，不用无限循环拖慢阅读。脚本失效时正文仍可见；新动画替换旧动画，页面隐藏或偏好改变时结束；观察器随重渲染清理。

## 4. 生成、实现、反馈

保留真实生图提示词、原始结果、选型判断、压缩参数与交付哈希。用原生 HTML/CSS/JS 实现排版与组件，把图作为独立素材接入。查看真实网页桌面、手机截图与动态录屏后修订，不把生成设计图当成最终网页截图。

首次整页 Pilot 需要基于真实截图生成两个结构受约束的页面方向，并按美观、层次、一致性、可读性、布局保留、代码可行性、响应式七个维度选择；局部迭代可只针对当前问题比较候选，本轮比较的是品牌艺术字。保留初始参考，不每轮重生整页。最多三轮主要视觉迭代，明显退化则回退相关修改。没有真正的生图或浏览器能力时应明确暂停相应阶段，不能以文字或虚构截图代替。

## 5. 必须通过的验收

1. 字体：实际平台字体为目标网页字体；覆盖当前全部动态标题；原生文本可选中，品牌图片失败有回退。
2. 动态：普通模式检测到真实浏览器动画且能按时结束；减少动态效果模式没有装饰动画；切换偏好能中止动画；快速连点不积累动画；导航标记在各宽度对齐。
3. 功能：四档宽度 320/390/768/1440 与五章回归；筛选、URL 刷新恢复、位置/CI、播放、CSV/SVG 下载、全屏按钮、图表库往返。
4. 可访问性与布局：axe 无严重/关键问题，无新增浏览器异常或资源失败，无页面横向溢出；图表自身可横向滚动。
5. 保真：原始数据、科学 SVG 与本轮未授权变更的业务文件保持一致；展示钩子单独核对；下载数据不变。
6. 性能：同机、同浏览器、同节流配置顺序比较基线与最终页面，保存原始报告。重点看资源增量、FCP/LCP、阻塞和布局位移，不只报综合分数；单次检测不能证明普遍提速。

本轮素材预算：标题字体 ≤60 KiB、艺术字 ≤20 KiB、动画 vendor ≤12 KiB、动画控制层 ≤8 KiB，合计 ≤90 KiB。若综合分下降超过 5 分、出现明显新增位移或读数不清，应先定位再交付；不能反复跑分只保留高分。

## 6. 可复查与发布

保留 before/after 截图、正常动态录屏、字体检查、功能与保真报告、性能原始结果、许可、复现命令及限制。`REPORT.md` 解释真实改善与未解决问题。将步骤变成可运行脚本；每轮失败先修正，再执行受影响检查。

发布使用已存在的 main → GitHub Actions → Pages。推送后必须等工作流成功，再核对公网 HTML、样式/脚本/字体/图片与本地交付版本一致，并实际打开公网页面验证。最终交付用户能直接访问的链接和版本标识。

未获得发布授权时不推送、不修改生产环境；不得强制重置或覆盖用户改动。保留可回退提交；不得输出凭据、购买额外服务或直接运行未经检查的第三方安装脚本。
