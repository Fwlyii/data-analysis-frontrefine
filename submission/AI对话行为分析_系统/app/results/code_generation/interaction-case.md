# 交互案例：低开销、低通过率条件如何失败

## 问题

在模型×Prompt 条件层面，短输出且低通过率的区域，失败主要发生在无法提取目标函数，还是函数进入测试后未通过？

## 用系统复现

1. 进入“代码生成 → 输出开销”，指标选 Pass@1。
2. 在“精确范围筛选”设置返回 token 0–150、通过率 0–10%，应用。也可以用散点框选同一区域。
3. 查看联动错误率，并点“Extraction error”柱；或用错误类型下拉选择“代码提取失败”后查看记录。
4. 通过评分列表打开单条记录，查看同条件的五次独立结果；可导出当前 CSV 或合并 SVG。URL 的 `codeBrush=0,150,0,10` 可恢复该集合。

## 可核对结果

选中 4 个条件，每个条件 193 题×5 次，共 3,860 条可评回答：

- Qwen2.5 / NoSpaces
- Qwen2.5 / NoProperGrammar
- Qwen2.5 / WordLimit(1)
- Qwen3 / OnlyNumbers

这些条件的平均 Pass@1 为 **3.08%**。全部可评回答中，代码提取失败 **3,269 / 3,860 = 84.69%**；测试断言失败为 177 条，属性错误 129 条，类型错误 43 条。提取失败子集覆盖 192 道出现该错误的题目，整个选区仍来自 193 道共同可评题。

这揭示所选低分条件的失效主要集中在输出协议/函数提取环节，不能只用代码逻辑能力解释它们的低分。提示限制针对代码前可选说明，完整 Python 代码要求保持一致。该发现同时涉及模型、Prompt、输出开销、Pass 与错误类型。

## 解释边界

选区由输出长度和分数共同定义，是探索性筛查；3.08% 本身不能作为长度导致低分的证据。它的分析价值在于继续用独立错误类型与评分记录定位失效环节。五次为独立单轮生成，没有前次回答或测试反馈，不是多轮修复。

来源为固定 code-generation@9dfc592 的 target-function-ast-v2 保存评分；整体共同环境排除 465 条，这些记录未进入选区分母。源快照、字段和错误率口径见 [代码方法](../../docs/code-generation.md)。统计可从 `app/data/code-evidence.json` 的模型×Prompt 条件重算；本次没有请求模型或执行生成代码。
