# 研究问题

本项目研究，怎样组织模型的输出、资料和反馈，让任务更有效地完成。我们从推理、文档问答和Python代码三个场景出发，把采集、清洗、分析和可视化整理到同一个项目中。接下来介绍五条有同题数据支持的发现。

# 实验规模

这些数据共有二十四万八千五百八十六条物理响应。推理方向包含六百道题，文档问答有两百道问题。代码生成是五次独立采样；代码修复才真正使用了上一轮程序和测试反馈。所有源文件保持原字节，清洗时保留缺失值与失败，不把环境问题算成模型错误。

# 分步回答的高分，可以用简洁表达保留下来

我们先研究最常用的分步提示。在同一批两百道基础数学题上，Qwen二点五只给答案时得分百分之二十二，改为分步解题后达到百分之九十一点五。接下来，只在原提示后加一句，保持简洁。输出从二百三十七个Token降到一百八十六，得分仍是百分之九十二。这个现象在三个任务方向反复出现：十七组全部更短，十五组得分点估计没有下降。简洁要求压缩了表达，却保留了有效的解题过程。

# 跨任务简洁现象

更重要的是，这并非单个模型单道题的故事。我们把推理、问答和代码的简洁提示对照放在一起。左边是输出缩短比例，右边是同一组题的得分变化。十七组的输出全部减少，两个略微下降的结果也原样保留。我们发现的是多个任务方向共有的表达压缩空间，各任务仍然使用自己的评价规则。

# 中文作答模板在 MATH500 上帮助多数模型省 Token、提分

第二个发现来自语言模板。题目仍然使用英文，我们只比较默认分步模板与中文作答模板。在MATH五百上，四个模型都更省Token，三个模型的得分提高。Qwen三从百分之五十八提高到六十九点五。Qwen二点五的截断率，从百分之二十二降到二点五。查看同题结果后，我们发现，许多得分改善的题，原先都没有在输出上限内完成。更紧凑的表达，有助于把答案真正交付出来。这个提分发现主要发生在较难的数学题上。

# 极端限长会引发输出反弹，格式处理挤占解题预算

简洁有效，不代表越短越好。我们把提示中的词数上限，从十个词压到一个词。十二组比较里，有九组的实际输出反而增加。图上七档都是真实采样，没有插值补点。一个因数题案例尤其直观：模型早已算出答案，却开始反复讨论怎样凑成规定的字母数，最后被截断。极端格式约束引入了额外任务，把本可用于完成答案的预算消耗掉了。

# 证据位置会改变问答表现，也会改变模型差距

接下来把注意力转向资料组织。我们固定问题、二十篇参考资料和提示词，只移动唯一相关的文档，测量了九个证据位置。位置的作用还与模型有关：相关证据放在第一篇时，Qwen三领先十六点五个百分点；放到最后，只领先二点五个百分点。升级模型带来的收益，依赖证据出现在哪里。Qwen二点五呈现较浅的U形，Qwen三主要表现为前置优势。我们用两条实测曲线共同说明模型与位置的关系。

# 模型与位置交互

将两条曲线作差，关系会更清楚。Qwen三相对Qwen二点五的优势，在首位最大，在末位显著缩小。首尾的模型增益差为十四个百分点，配对区间不跨零。位置不是一个只影响所有模型相同幅度的因素，它改变了模型升级能带来的实际收益。

# 具体执行反例比笼统检查更能推动多轮代码修复

代码方向，我们采用了多轮代码修复。两组模型在同一道题上共享初稿，再分别接受四种处理：独立重采样，自行检查，只告知是否通过，或者提供具体失败输入、预期结果和实际结果。Qwen三到第四轮时，具体反例通过一百四十一题，自行检查通过一百二十九题。初始诊断测试失败的三十题中，自行检查修好三题，具体反例修好十五题。这个实验研究的是反馈如何帮助模型定位错误，与前面五次独立采样有明确区别。

# 代码任务的比较边界

原代码生成实验还有九万多条保存回答，它们是独立采样，不能称为多轮修复。增加采样的覆盖收益主要集中在前几次。真正的修复实验，必须给模型上一轮程序和诊断信息，再观察后续版本。我们把两个实验的数据、脚本和指标分开保留，也把环境排除与模型失败分开。

# 可复现管道

最后，我们把所有材料整理成了一个完整仓库。冻结原始文件、清洗数据、分析、绘图和网页都有独立入口。统一匿名索引保留了全部物理响应，缺失值不补零。系统可以切换任务、模型和位置，也可以逐轮查看代码修复。另有一个按课程目录树生成的匿名提交版本，带数据字典、当前报告和答辩材料。

# 结论

总的来说，我们形成了五条主发现。分步解题可以保留，冗余表达可以压缩。中文模板帮助多数模型完成较难数学题。过度限长可能产生反弹。模型升级的收益依赖证据位置。具体执行反例则让代码修复更有方向。这五条发现覆盖两条低维规律、两条多维关系和一条异常现象，也都能在系统图表与保存统计中找到依据。
