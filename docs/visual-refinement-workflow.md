# LENS 全站视觉优化流程

本流程以 `dataAnalysis-vision` 的 **Master** 为科研内容基线，覆盖演示首页与图表库。Master 视觉重建保存在 [`optimization/master-rebuild-v6`](../optimization/master-rebuild-v6/)；最新「知微之门」导航空间和验收保存在 [`optimization/knowledge-gateway`](../optimization/knowledge-gateway/)。历史参考保留，当前网页不会加载旧版 site/deck 皮肤。

## 知微之门入口改造

默认首页和 `#gateway` 为沉浸导航空间，五个球体分别进入原有 `#question`、`#collection`、`#cleaning`、`#landscape`、`#findings`。原研究问题内容继续通过第一个球体访问，图表库与辅助入口仍保留。当前共93个受检状态。

此轮复用已经完成的5.95秒开场，只改变最后的共享场景交接：同一组五个链接节点从微光变为球体，同一个光学 SVG 留在首页。内页深链接继续使用原品牌落入页眉的路径。没有引入生图位图、视频或新的大型依赖；这是纯代码交互场景，素材与布局方法依任务选择，不强制为已有可编辑光学 SVG 另造位图。

新检查需额外验证 DOM 身份连续、无重复透镜、早期跳过、重播、鼠标聚焦暂停漂移、点击后真实路由、触摸输入、手机独立布局、可访问性、后台暂停及窗口变化。测帧与 Lighthouse 独立顺序运行。最初仅授权本地开发；用户随后明确要求推送本版预览。发布以最新用户授权为准，仍需等待工作流成功并核对线上产物。

## 方法来源与工程改造

- [Editable Visual Design](https://arxiv.org/html/2609.04034v2)：借鉴先生成视觉参考、原生代码与视觉素材分离、用渲染反馈修正的闭环。其海报等固定画布场景不能直接当作响应式网页方案。本项目没有引入作者的编辑器或执行其代码。
- [UI Remix](https://arxiv.org/html/2601.18759v2)：借鉴集中探索及组件局部改造，约束每轮保留结构、文案和功能。本项目没有实现论文的检索库、MMRAG 或用户研究。
- [UI2Code-N](https://proceedings.mlr.press/v306/yang26v.html)：借鉴执行、观察真实渲染、相对比较和局部 polishing。没有训练其模型、复现 RVPO 或宣称达到论文的测试成绩。

这是把方法用于现有科研网站的工程流程，不能将本项目的效果称为三篇论文已经验证的结论。此前全文阅读记录保存在 [Pilot 方法笔记](../optimization/homepage-pilot/research/method-notes.md)；本轮重新核对了上述论文及 Editable-Design 作者仓库。后续轮次也应核对方法与当前任务是否相符。

## 1. 先恢复可验证的内容基线

1. 确认工作区并备份当前版本。本轮备份分支为 `backup/before-master-rebuild-v6-fc71df5`。
2. 使用 `git ls-remote` 核实实际分支名称；本项目是大写的 `Master`。
3. 重新克隆 `https://github.com/Fwlyii/dataAnalysis-vision.git` 的 Master。本轮源提交为 `35f7318e45561da07c75eaf65374e4107004d5ec`。
4. 将它的文件导入 main，移除上一轮在生产目录额外加入的视觉文件。保留 Git 凭据、Pages 工作流、历史优化记录。导入不需要强制推送。
5. 检查 LFS：网页用的三个压缩数据集必须是实际数据，并逐一匹配上游指针中的 SHA-256。研究归档的 LFS 指针不需要下载为网页运行依赖。
6. 原样构建并保存可独立运行的基线。`73a1e8c` 是本轮恢复基线的独立提交，后续视觉修改从这里开始。

## 2. 枚举全站，截图后再设计

不能只截首页。执行 `scripts/inventory.mjs`，从真实源码枚举页面状态，包括五个演示部分、三个方向全部模型的两种全景视图、五类发现及全部筛选组合、13 种图表、4 种代码视图、5 个发现章节、论文图和有意的空状态。本轮共 92 个状态。

截图需记录 URL、视口尺寸、系统动态效果偏好、数据选择、实际激活面板；图表必须已绘制，图片必须已解码，字体必须已加载。桌面与手机都需要截图；检查尺寸包含 320、390、768、1366、1440。长图表保留可读尺寸，允许容器内滚动，并提供提示和键盘入口。

## 3. 把真实截图交给生图模型

使用 imagegen 技能，先查看本地输入截图，再向生图模型提供截图与完整约束。提示词必须包含：

- 网站任务、读者、必须保留的原文与数据；输入截图分别来自哪里。
- 精确视口、顶栏与导航尺寸、文字安全区、图表可滚动范围。
- 候选配色、字体、标题层级、留白、图标和按钮状态。
- 首页、内容页、图表库、手机布局和开场动画分镜。
- 禁止替换真实科研图表、编造数值、将文字或数据烘焙进背景图。

先生成至少两套可比较的方向，再选择符合原项目用途的方案。本轮选择 A：深蓝首页、纸色内容、铜色强调。生成图是视觉参考，不是正确性证明；图中的额外侧栏、错误标签等必须由 Coding Agent 纠正。英文大标题使用本地 Fraunces 字体，界面保留 Geist；科研图表继续使用原版的几何与数值。

选择时逐项比较美观、层级、一致性、可读性、结构保留、代码可实现性和响应式适配，记录定性理由。本轮两个候选共同生成在一张对照板中，A 的编辑式标题更接近 Master；B 的粗体标题改变视觉重心更明显。没有把主观评价伪装成客观分数。

设计解析必须区分三类：A 为代码实现的排版、边框、容器与几何装饰；B 为确有必要时独立生成的复杂艺术素材；C 为必须保留原生的文字、表单、数值与科研图表。本轮新方案不需要 B 类运行时位图：原 Master 已有可编辑的光学 SVG，开场又明确要求纯代码，因此保留它们。后续如需复杂插画，应另写素材提示，指定用途、尺寸、安全区、透明背景与无文字要求，独立生成并验证解码和体积，不能从整页稿直接截出信息区当网页。

## 4. 将方案整理为 Codex 可执行任务

交接文件为 [`codex-implementation-brief.md`](../optimization/master-rebuild-v6/codex-implementation-brief.md)。必须列出：采用哪张设计稿、哪些建议采用/拒绝、具体修改文件与选择器、不能修改的数据与逻辑、动画时间轴、手机策略、失败降级、验收命令。当前会话中的 Codex 实际执行了这些代码修改；没有声称另外调用一个不存在的 Codex 服务。

生产实现使用原版 `story.css` / `styles.css` 加一份明确的 `refinement.css`。图表库与演示页共享这份呈现层，不再叠加多轮 site/deck 皮肤。图表数据与图形绘制函数保持原版。装饰使用原生 SVG/CSS；科研图表仍是可交互、可导出的真实图形。

## 5. 开场动画作为全站设计的一部分

纯代码 Canvas + SVG + 原生文字构成 5.95 秒开场：粒子、汇聚光流、镜片、研究符号、品牌、落入真实顶栏。与页面共享深蓝、米白、铜色变量；最终位置由浏览器测量实际品牌坐标。

必须支持跳过、Esc、重播、会话内只自动播放一次、`?intro=1` 强制播放、`?intro=0` 跳过、系统减少动态效果偏好。动画期间底层页面继续初始化并暂停交互；结束后释放 RAF、Canvas、焦点锁和临时样式。Canvas、存储或脚本失败、延迟加载、页面隐藏、切换路由及窗口变化都必须能安全回到页面。审查录屏只作为证据，网页不能加载它作为开场。

## 6. 实现后截图，再交给生图模型反馈

第二轮输入必须是代码实现后的真实浏览器截图，不能仍然使用原始设计图。本轮 `design/screenshot-feedback.png` 反馈后修正了桌面轨道端点裁切、手机轨道穿过正文、图表标题与筛选器层级。每次记录问题、采用的建议、代码调整与最终截图。

视觉审查与功能审查分开：检查通过只说明已验证的技术条件，不说明用户一定喜欢审美。逐页查看标题、图文关系、图表大小和手机阅读节奏，不能以首页代替全站。

## 7. 详细检查并把证据绑定当前源码

1. 清理可重建的 `app/runtime` 生成目录后标准构建，验证静态资源与图表绑定；dist 中的脚本清单必须与当前构建模块完全一致，防止历史生成脚本残留。CI 从干净 checkout 构建。
2. Master 内容、研究数据、图表几何对照。
3. 92 状态 × 5 尺寸的真实渲染检查；保存桌面和手机截图。检查图片解码、可见 SVG 的实际绘制、失效引用、NaN、外层溢出和激活状态；Plotly 的空 hover 图层必须明确识别。
4. 真实点击、筛选、刷新、历史返回、表格、键盘、抽屉、导出文件与代码示例。
5. 关键页及弹层的 axe 可访问性检查。
6. 开场完整播放、跳过、故障降级、重复播放及帧采样。性能测量单独运行，避免其他浏览器任务干扰。
7. 本地 Lighthouse 前后配对诊断。注明网络/CPU条件，不能冒充真实手机或弱网性能。
8. 保存当前生产源文件的 SHA-256；修改代码后相关证据必须重新生成。Pages 发布前执行 `scripts/system/check_visual_coverage.py`，阻止使用过期或缺页的证据。
