# 前端视觉优化流程 v4：跨仓库迁移、全站覆盖与生图迭代

适用当前 LENS 原生静态前端。保留内容、数据含义、路由和交互，先明确整站范围，再逐轮改善布局与审美。第三轮样例见 `optimization/site-consistency-v3/`；前两轮参考、提示词和报告保留在原目录。

本轮业务来源为 `Fwlyii/dataAnalysis-vision` 的 **`Master`**（区分大小写），提交 `35f7318`；已发布视觉来源为当前仓库 `a1cd05a`。成果集中在 `optimization/master-migration-v4/`。

2. 先核对架构变化。最新首页新增五部分展示与原生动态 SVG，不能把旧首页整份覆盖过去。原图表库仍沿用相同业务代码，因此复用之前的公共样式；新增页采用共用变量加独立 `deck.css`。品牌与字体、背景与表面、导航指标、图表容器、弹层和章节过渡一起迁移。
3. 页面清单从最新内容和源代码生成：五部分入口、全貌的所有方向/模型/两种视图、五个发现与 36 个限长组合、13 类图表及代码视图。本轮 92 个状态，不沿用之前的固定 34。每个状态实际检查显示内容和控件选中项，四档宽度，桌面及手机真实截图。
4. 生图流程仍为两方向 → 真实实现 → 真实手机截图定向修订。模型可能改错研究名称或忽略布局要求；逐项记录拒绝的内容，只采纳能保留原始数据和功能的建议，不将模型文字或数值接入系统。电影开场仍为纯代码，参考图和录屏只用于审阅。
5. 数据保真同时覆盖新业务和旧视觉：冻结统计、原始图稿和业务渲染函数与 Master 对照；新动态图稿仅允许颜色映射变化，几何和数字生成代码不变。修复原有错误也应列明触发条件与回归检查，不能当作任意更改路由的理由。
6. 测试必须适配新架构语义。新页面原本采用固定视口、面板内滚动，开场结束应移除开场锁定和 inert，不能要求原布局变成整页滚动；筛选使用 replaceState、章节使用 pushState，分别验证刷新与返回。滚动表格、长响应、热图需能用键盘操作。
7. 完成构建之后才运行浏览器与资源检查，不能边写 dist 边验收。源文件、字体、模板、构建器和装饰素材都写入证据指纹；更改后重新检查，不能给旧截图换上新的指纹。
8. 最新规范目录为根目录 `scripts/system/`、`docs/`、`reports/`，不再使用原匿名包的 `app/pipeline/`。`app/runtime` 与 `app/dist` 为构建产物，不入 Git。GitHub Actions 使用根目录构建器与新的覆盖门禁。
9. 保留上游科研档案的 LFS 指针与原仓库端点；部署所需三个小型 `.gz` 冻结快照校验上游 SHA-256 后直接存入当前 Git，发布构建不需要下载约 1 GiB 研究档案。`submission/` 是上游历史提交包，不属于生产导航，不假装成已迁移的另一个在线站点。
10. 验收成功后按本轮用户明确授权推送当前仓库 `main`，等待 Pages 成功，再核对公网资源哈希和真实导航、开场重播/跳过、手机与减少动态效果。另一源仓库 `Master` 保持原样。

## 1. 前三轮经验

首轮依赖系统字体和静态截图；第二轮补了本地字体、艺术字和动态检查，但仍把首页作为主要目标，图表库只测了往返。因此首页通过不能说明整站统一。旧图表库的紫色主题、独立页眉、零散筛选器和拥挤手机导航都被遗漏。

本轮先统一公共设计来源，再枚举全部视图。验收核对实际显示的标题、当前导航和图形，不能只核对网址或 HTTP 200。尤其是同一文档中只改变 # 的导航，自动化可能仍显示旧视图；截图工具必须打开新文档或执行实际页面操作，并独立检查当前选中项。

方法仍借鉴首轮已阅读的 [Editable Visual Design](https://arxiv.org/abs/2609.04034) 的视觉想象与独立素材、[UI Remix](https://arxiv.org/abs/2601.18759) 的保留结构局部改造、[UI2Code-N](https://proceedings.mlr.press/v306/yang26v.html) 的真实渲染反馈。全站覆盖、响应式、字体、动态和发布检查是工程补充，不声称这些论文验证过这一组合。阅读记录见 `optimization/homepage-pilot/research/`。

## 2. 先建立全站清单

- 记录基线提交、工作区改动和发布授权，在独立分支工作，保留用户已有修改。
- 每轮建立新的成果目录，以最新已发布提交作为基线；复制并适配上一轮检查工具，更新结果路径和覆盖清单。历史 before、设计图和报告保持原样，不把下轮结果写回旧目录。
- 遍历生产 HTML、站内链接、顶栏模式、章节、图表枚举、代码视图、弹层，以及筛选、空结果、详情和刷新恢复状态。区分物理页面、同页状态、下载文档；每项有进入方法与覆盖状态，排除项需要理由。
- 运行 `node optimization/site-consistency-v3/scripts/inventory.mjs`。本轮有两个入口和 34 个验收状态：首页五章及两种任务变体、输出效率两视图、资料位置两视图、代码生成四视图、更多发现五章、13 种图形及一个空状态。统计方法、条件记录、匿名详情和代码评分弹层另做操作检查。
- 为每项记录四档宽度、截图、实际选中项、字体、主要交互和遗留问题。默认首页只能是第一张参考，不能是整个验收范围。PDF/CSV/SVG 下载作为文档和导出检查，不假装成新的网页。
- 新增入口、模式、章节或图形必须更新清单。图形/代码视图/首页章节枚举从源代码读取，新生产 HTML 或未知模式会阻止清单生成。

## 3. 公共设计先于页面装修

公共变量与品牌字由 `app/site.css` 提供；两种布局的页眉分别使用 `app/templates/deck-header.html` 与 `app/templates/site-header.html`；构建器将模板写入两份入口，业务页只负责自身布局。不要给每个页面复制一套颜色和页眉。

跨页对照品牌尺寸、背景、正文颜色、标题字体、导航间距、按钮、选择器、图纸、表格、焦点、弹层和动态节奏。模型颜色、点型、单位与坐标属于科学图的信息编码，不能为装饰统一而改动。

标题字体必须有明确许可，记录母版哈希、子集工具、覆盖字符和准备脚本；从全部实际动态标题收集字符，不能仅取首页文案。用浏览器的实际平台字体检查缺字与回退，不能只检查 font-family。新增标题需要更新子集。正文、按钮、表单、普通标题和数据保留原生文字；特殊品牌艺术字可以独立生图，但必须保留原生可访问名称与图片失败回退。

## 4. 至少两次真实的生图参与

布局与审美任务按下面的闭环执行，最多三轮主要视觉迭代：

1. 取代表页面和相邻页面的真实桌面/手机截图，向生图模型说明品牌、已有内容、原布局约束和不能改变的数据。
2. 真正生成两个方向，按美观、层次、一致性、可读性、布局保留、实现可行性、响应式七个维度比较，记录模型没有遵守的约束，选择综合较好的方向。
3. 原生实现第一版。复杂装饰需要时独立生成素材；普通布局、几何、卡片、字体、按钮用代码，不能把整页图当界面。
4. 再看真实浏览器截图，将最大的布局问题连同截图交给生图模型产生针对性修订，而不是只在开头调用一次模型。
5. 根据修订图做第二轮代码与浏览器反馈；跨页检查公共组件是否一致。明显退化则回退该轮相关变更。

本轮实际是“两份桌面方案 → 第一版代码 → 手机真实截图 → 生图手机修订 → 第二版代码”。保留提示词、输入角色、原图、选型理由、交付资产哈希和迭代记录。生成图里的文字、坐标、模型图标与数值可能有误，生产页面必须取原始数据和组件。没有真正生图或浏览器能力时明确暂停相应阶段，不能用文字或虚构截图代替。

纯代码实时动画任务采用“分镜 → Canvas/SVG/原生文字 → 真实浏览器截图与录屏 → 定向视觉迭代”的分支。当前电影开场按用户要求完全由代码生成，不强制执行上面的生图步骤，也不把录屏或生成图作为运行素材。仍保留跨尺寸、字体、可访问性、性能、清理和原系统回归检查；用户明确限定本地开发时不进入发布步骤。

## 5. 动态设计与实现

先定义触发、对象、终态、时长、减少动态效果、快速重复触发和页面隐藏时如何处理，再选择库。沿用第二轮核对的本地 Motion mini 14.9.0，保留 MIT 和打包输入；必要时才检索新方案，核对当前官方仓库、许可、API 与实际交付体积。

章节和模式变化给标题/图纸 350–550ms 的轻入场，导航标记约 420ms，条件变化与弹层 220–350ms。只动画展示层 transform/opacity，不插值实验数值或科学曲线。没有装饰无限循环；内容默认可见。快速触发替换旧动画，重渲染清理旧目标，减少动态效果偏好改变或页面隐藏时结束。普通模式要检测真实动画并录屏，减少动态效果模式要检查没有装饰动画且功能完整；静态截图不能代替动态验收。

## 6. 验收必须跨页面和状态

- 覆盖：34 状态 × 320/390/768/1440 四档宽度；桌面和手机保存成对截图，核对实际选中项、主标题、真实图形或明确空状态。新增状态同步扩展，不能固定把数字 34 当作永远完整。
- 一致性：两页共同加载共享样式与脚本，同品牌、背景、导航和标题字体。不得用 overflow:hidden 掩盖页面溢出；宽科学图在自身区域滚动，区域需支持键盘聚焦。
- 交互：首页原功能、顶栏模式、筛选与刷新恢复、SVG/CSV、位置矩阵 → 400 行记录 → 匿名详情 → 联动探索、代码采样播放、错误选择、数值范围与清除、评分详情、全屏按钮及两页往返。
- 可访问性：主要页面与弹层做 axe 检查；关注悬停/选中态的真实对比度、滚动区域、动态 SVG 名称、键盘焦点与关闭后恢复。失败先修复，不只挑一个通过页面报告。
- 保真：数据、原科学 SVG、统计和路由保持原样；展示或可访问性注释要列出具体例外并核对其余源码一致。导出核对真实文件与当前筛选集合，不能只判断按钮存在。
- 性能：同浏览器、同主机、同视口和同节流方法顺序比较两个入口，保留原始报告，记录资源增量、FCP/LCP、TBT、CLS。单次分数不是普遍提速证据，不同节流方法不能混比。图表库已有大体积快照，本地无节流诊断不代表弱网与真实手机体验。

本轮预算：共享标题字体 ≤90 KiB、共用 CSS ≤8 KiB、公共展示脚本 ≤8 KiB；品牌图与 Motion 复用已有版本。按冷加载及跨页缓存分别记录。若同条件性能下降超过 5 分、有明显新增位移、控件不可达或读数不清，先定位再交付，不重复跑分只保留高分。

## 7. 证据与发布检查

执行顺序：基线与当前预览 → inventory → before 截图 → 生图与代码迭代 → after 截图 → `site-checks.mjs` → 首页原功能回归 → 真实录屏 → 同条件性能 → `finalize-review.py` → 授权范围内发布与公网检查。端口和命令见本轮 REPORT。

`site-checks.mjs` 保存检查时的源码指纹；`finalize-review.py` 仅在检查通过且源码仍匹配时更新 `app/visual-coverage.json`。GitHub Actions 上传前执行 `check_visual_coverage.py`，核对入口、源码视图枚举、真实视图截图、浏览器结果和源码指纹。新增入口、漏测、失败或过期证据会阻止发布。这一步只校验证据，不会假装重新执行浏览器。只修改报告等不影响页面的内容可以沿用仍匹配的证据。

发布后等待 Actions 成功，核对公网两个入口、公共 CSS/JS/字体/图片与本地版本，再实际打开两页验证导航和动态。交付用户可点击的预览链接、报告、限制与版本号。

## 8. 保留边界

不得删除用户改动、强制重置历史、泄露凭据、擅自付费或运行未经检查的第三方安装脚本。无发布授权时保留可审阅结果，不推送或修改生产。保留独立提交供正常 revert 回退；截图与设计方案不能覆盖原始参考。覆盖的是明确列出的主要状态和关键操作，不声称穷尽每个数据组合、全部浏览器或真实设备。
